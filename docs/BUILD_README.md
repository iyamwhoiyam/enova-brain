# Enova Brain — build bundle

This is the complete, self-contained build of **Enova Brain** (the Enova Science internal ERP/dashboard). You can run, edit, verify, and deploy everything from this folder — including on an external drive.

Generated 2026-07-17. Latest build: two operational fronts + May-2025 scope, all 36 regression checks green.

---

## 1. What each file is

**The app (this is the whole product):**
- `Enova_Brain_Studio_2.html` — **THE SOURCE OF TRUTH.** The entire app is this one file (React 18 + JSX compiled in-browser via Babel). *Edit this file* to change the app.
- `index.html` — deploy copy of the source (what you push to GitHub → Vercel). Identical to `Enova_Brain_Studio_2.html`.
- `index.prod.html` — production build with the JSX pre-compiled (no in-browser Babel; faster load). Optional; generated by `build_prod.js`.
- `index.offline.html` — fully self-contained build (React, Babel, xlsx, decimal all inlined; no internet needed). Great for the external drive / a laptop with no network. Generated by `build_offline.js`.
- `enova_brain.js` — the portable deterministic **kernel** (costing, formulate, packaging, label engines). It is embedded inside the HTML; this standalone copy is the editable source, re-synced with `resync_kernel.js`.

**Build & verify scripts (need Node.js):**
- `verify.js` — Babel parse gate. `node verify.js` must print `BABEL PARSE: OK` before shipping.
- `build_prod.js` — writes `index.prod.html`.
- `build_offline.js` — writes `index.offline.html`.
- `resync_kernel.js` — re-embeds `enova_brain.js` into the HTML after a kernel edit.
- `run_all_tests.sh` — the full regression suite (36 checks). `bash run_all_tests.sh` → must end with `ALL … CHECKS PASSED`.
- `test_*.js` — deterministic unit/golden tests (pure Node).
- `shoot_*.js` — real-browser drives (need Playwright + Chromium).
- `package.json` — dev dependencies for the tests.

**Data / catalog:**
- `_sourcing_catalog.json`, `_sourcing_mined.json` — the ingredient sourcing knowledge base (287 ingredients mined from completed formulas).
- `build_catalog.js`, `expand_inv.js`, `mine_sheets.js` — rebuild the catalog from completed sheets.
- `_corpus_cases.json`, `enova_extract.json` — test fixtures / extraction data.

**Docs on disk:** `Enova_Brain_Kernel_Architecture.md`, `Enova_Generator_Validation_Scorecard.md`, `How_Formulation_Software_Works.md`, `RUNBOOK.md`, plus this README. (The full design/planning doc set lives in the Claude project — see §6.)

**`backups/`** — timestamped snapshots of the source (one included: the latest). Keep making these before big edits.

## 2. Just run it (no install)

Double-click **`index.offline.html`** — it opens in any browser with zero setup and zero network. This is the easiest way to run from the external drive.

`index.html` / `index.prod.html` also run in a browser, but they load React from a CDN (needs internet) and connect to the live **Supabase** database for real project data.

---

## 3. Edit → build → deploy (needs Node.js 18+)

```bash
# one-time: install dev deps for the build/test scripts
npm install
export ENOVA_NG="$(pwd)/node_modules"     # scripts read node_modules from here
# (optional, for the shoot_*.js browser tests)
npm install -D playwright && npx playwright install chromium

# after editing Enova_Brain_Studio_2.html:
node verify.js                 # 1) Babel parse gate — must say BABEL PARSE: OK
node build_prod.js             # 2) rebuild the prod variant
node build_offline.js          # 3) rebuild the offline variant
cp Enova_Brain_Studio_2.html index.html    # 4) refresh the deploy copy
bash run_all_tests.sh          # 5) full regression suite — must be ALL CHECKS PASSED
```

If you edit the kernel (`enova_brain.js`): run `node resync_kernel.js` to re-embed it, then verify.

**Deploy:** commit `index.html` to your GitHub repo → Vercel serves it. That's the whole deploy.

> Note: `ENOVA_NG` just tells the scripts where `node_modules` is. On this machine it defaulted to a global path; setting it to `$(pwd)/node_modules` after `npm install` makes the bundle fully portable.

## 4. Standing rules (how this codebase is maintained)
- Babel parse after every edit; never ship code that fails to parse.
- Keep the regression suite green; keep a verified backup before big changes.
- Fix surgically — never drop working features or data.
- Formula rule: never invent ingredients, quantities, or prices; every cost traces to MISys / the Master Bid / the sourcing catalog / an explicit manual entry. Tier pricing is manual.
- Every generated item requires an Enova employee's review before it is saved or sent.

## 5. Live data (Supabase)
`index.html` reads/writes the `enova-brain` Supabase project (`studio_projects` table). The publishable anon key is embedded in the file. `index.offline.html` falls back to the built-in seed if it can't reach Supabase.
